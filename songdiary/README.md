# 소리일기 (Sori Diary)

노래 연습·녹음·일기를 담는 Capacitor(Android) 앱 `com.songdiary.app`의 웹 소스와 APK 재빌드 도구입니다.
첫 커밋은 `노래일기-1.0.0.apk`의 `assets/public`을 그대로 꺼내 온 것이에요.

## 새 디자인과 연습 화면

첫 화면에 스케일·녹음·한 줄 기록 바로가기를 두고, 하단 기록 탭에서는 일기를 먼저 보여 줍니다.
시작 전 → 연습 → 노래·녹음 → 마무리를 이전/다음으로 오갈 수 있어요.
피아노는 Yamaha C5 녹음을 48 kHz 16-bit(CD 음질) 스테레오 무손실 FLAC으로 포함합니다 (24-bit는 APK가 커져서 드라이브 업로드가 막혀 16-bit로 줄였어요).
빠르기는 40/60/80(기본)/100/130 BPM(같은 BPM에서도 8분음표 연습은 4분음표 연습보다 두 배 빠르게 들려요: 책의 리듬), 마지막 음은 0.4초 더 길게 울려요, 자동 진행은 상행 시작/하행만을 선택합니다.
계이름·건반 표시가 실제 음을 따라가고, 시작음과 꼭대기음은 독립적으로 저장되며 재생 중 변경도 다음 묶음에 이어집니다.
멀티윈도우 설정과 앱 복귀 복구는 새 APK를 설치해야 적용됩니다.
검토 내용·검증·호환성: [UX_REVIEW.md](docs/UX_REVIEW.md).

## 구성

- `www/` — 앱 화면 전체 (빌드 과정 없는 순수 HTML/CSS/JS)
  - `app.js` 화면·기록 로직
  - `songsearch.js` 노래 찾기 (초성·부분 입력 매칭, Apple Music 곡 검색)
  - `scales.js` 스케일 연습 (Singing for the Stars 1~26번 스케일, 기본 스케일, 계이름, 마이크 음정 인식)
  - `practice.js` 노래 전 루틴 (Singing for the Stars), 책의 주의 사항·27~30번, 강의의 발음 찾기·노래할 때 기억할 것·목 보호 규칙
  - `update.js` 앱 안 업데이트 (서명된 새 버전 확인·받기·바꾸기)
  - `cloud.js` 계정·동기화 (Supabase: 이메일 번호 로그인, 기록·녹음 저장)
  - `release.json` 이 버전의 번호와 파일 목록 (`tools/publish_update.py`가 만듦)
  - `native.js` 저장소(IndexedDB)·백업·네트워크·안드로이드 연결
  - `fonts/`, `fonts.css` Gaegu · IBM Plex Sans KR (앱 안에 포함, 오프라인 동작)
- `release/` — 앱 안 업데이트로 내보낸 버전
  - `latest.json` 앱이 확인하는 최신 버전 목록 (서명됨, main 브랜치에서 읽음)
  - `files/<sha256>` 그 버전의 파일들 (이름이 곧 내용의 sha256이라 한번 올린 파일은 바뀌지 않음)
- `cloud/` — Supabase 준비 안내(`README.md`)와 표·규칙(`setup.sql`)
- `tools/build_apk.py` — 안드로이드 SDK 없이 APK를 다시 만드는 스크립트
- `tools/publish_update.py` — 앱 안 업데이트용 새 버전을 서명해서 내보내는 스크립트

## 가사 노트

기록 → 곡별 → 노래 → **가사 노트 · 기교 표시**. 가사를 붙여 넣으면 줄 노트에 한 글자씩 띄우고, 글자를 눌러 기교를 표시해요.

- 기교 23가지를 중요한 순서로: 숨 쉬는 곳 · 숨소리 섞기 · H 어택 · 밴딩(올려 잡기) · 바이브레이션 · 끝 숨 빼기 · 폴 · 꺾기 · 가성 · 믹스 전환 ·
  성대 붙여 시작 · 이어 부르기 · 끊기 · 길게 · 강세 · 세게/여리게 · 울먹이기 · 프라이 · 런 · 비음 · 허스키 · 박자 밀기.
- **발음** 도구로 글자마다 실제로 부를 발음을 적고(빨간 글씨), **메모** 도구로 줄마다 메모.
- **들으며 체크**: 중요한 기교부터 하나씩 “이것만 들으며 한 번 듣기”를 체크해요. 지금 들을 기교를 알려 줘요.
- 가사를 고쳐도 바뀌지 않은 줄·글자의 표시는 그대로 옮겨져요(`LyricNote.remap`). 저장은 곡 정보(`settings.songs[].ly`)에 되고,
  두 폰에서 같은 곡을 고치면 가사 노트는 나중에 고친 쪽이 남아요.

## 노래 찾기

노래 제목 칸에 몇 글자만 치면 노래방 리모컨처럼 찾아 줍니다.

- **내가 부른 노래**: 폰 안의 기록에서 바로 찾음. 초성(`ㅂㅇㄱ` → 밤양갱),
  띄어쓰기 무시(`사건의지평선`), 입력 중인 글자(`밤야` → 밤양갱), 가수 이름 모두 됨.
- **실제 노래**: [iTunes Search API](https://performance-partners.apple.com/search-api)
  (한국 스토어)에서 곡을 찾아 가수·앨범 사진·30초 미리듣기를 붙임. 키가 필요 없고,
  앱 안에서는 Capacitor 네이티브 HTTP로 요청해서 CORS 문제가 없음.
  보내는 건 검색어뿐이고 일기 내용은 보내지 않음. 설정에서 끌 수 있음.

노래방 곡 목록 전체(수만 곡)를 앱에 넣는 방법도 있지만, 자유롭게 쓸 수 있는 데이터가 없고
금방 낡기 때문에 온라인 검색 + 내가 부른 노래 목록(오프라인) 조합을 택했어요.
추가되는 용량은 코드 몇 KB뿐입니다.

## 스케일 연습

오늘 화면 ‘기초 연습’의 건반 버튼(루틴의 립롤·혀 트릴·책 진도 줄에는 ‘건반’)으로 엽니다.

- 건반은 **0옥 도(C2)**부터 3옥 도(C5)까지. 누른 음을 ‘도’로 삼아 시작해요.
- **시작 음**: 책 스케일은 책의 **테너** 시작 음에서 열려요 (1옥 도 C3 · 5/7/10/11/19/20/22~24번 1옥 솔 G3 ·
  21번 1옥 솔# · 12번 2옥 도# · 25번 2옥 솔 · 14번은 표기가 없어 2옥 도). ‘시작 음 ▼▲’이나 건반으로 더 낮게(0옥 도까지)/높게 바꾸면
  연습마다 기억하고, ‘책대로’로 되돌려요.
- **자동으로 오르내리기**(기본 켜짐): 시작을 한 번 누르면 스케일이 끝날 때마다 반음씩 올라가서, 스케일의 가장 높은 음이
  **꼭대기 음**에 닿으면 다시 반음씩 내려와 처음 음에서 끝나요. 책은 올라가기만 하고, 내려오는 쪽은 앱이 채웠어요.
  꼭대기 음은 ▲/▼로 바꿔요 (안 바꾸면 내 최고음, 없으면 첫 번째보다 5음 위). 건반에 ‘꼭대기’로 표시돼요.
  루틴 항목에서 열면 한 번 다 오르내릴 때 1회 체크되고, 립트릴 1번 → 3번처럼 다음 연습으로 넘어가요.
- **Singing for the Stars 1~26번 스케일 전부**: 1부 자신감 쌓기(1~13번), 2부 스피치 레벨(14~26번).
  책의 음·리듬 그대로예요 (3/4박자, 8분음표·늘임표·붙임줄·끊어 부르기, 14번은 미끄러지는 소리).
  번호마다 책의 방법, 부를 소리((a) 멈 (b) 거 …), 시작 높이, 연습 일지(시작한 날·해낸 날)가 나와요.
- 기본 스케일(5음, 3음, 아르페지오 등)과 계이름으로 만드는 **내 스케일**(30개까지)도 그대로 있어요.
- **피아노 소리**: 실제 그랜드 피아노 녹음 — [Salamander Grand Piano V3](https://archive.org/details/SalamanderGrandPianoV3)
  (야마하 C5, Alexander Holm, **CC BY 3.0**). 0옥 라~5옥 도를 3반음마다 하나씩(22개, `www/piano/p<midi>.mp3`, 스테레오 6초, 약 1.3MB)
  넣고 그 사이 음은 가장 가까운 녹음의 높이를 바꿔 내요. 앱 안에 들어 있어서 인터넷 없이도 돼요. 녹음을 읽기 전 잠깐은 예전 소리.
- 빠르기 5단계(아주 느리게 40 ~ 매우 빠르게 130), 시작 전 기준 화음, 지금 나오는 음 표시(건반·계이름). 범위 밖으로 올라가는 음은 흐린 건반으로 보여 줌.
- **따라 부르기 박자**: 피아노가 끝나면 같은 박자를 한 번 더 짚어 줘서, 듣고 따라 부르는 연습을 할 수 있음.
- **내 음 보기**: 마이크로 부르는 음을 인식해 건반에 초록색으로, 목표 음과 맞는지 막대로 보여 줌
  (YIN 음정 인식, 인터넷 불필요). 목소리가 피아노보다 늦는 만큼(약 0.25초) 이전 음과 비교하고,
  한 옥타브 차이는 같은 음으로 봄.
- 스케일 꼭대기 음을 그날 ‘최고음’으로 바로 기록하고, 기초 연습 항목에서 열면 1회 체크도 돼요.

## 노래 전 루틴 (Singing for the Stars)

세스 릭스(Seth Riggs)의 *Singing for the Stars*로 짠 루틴이에요 (약 27분). 히싱·개호흡은 강의에서 하던 그대로 두었어요.
‘기초 연습’의 ‘노래 전 루틴 넣기’로 넣고, 예전 강의 루틴(`rt_*` 항목)을 쓰던 폰은 앱을 열면 저절로 바뀌어요.

**오늘 연습 따라 하기**: ‘기초 연습’ 맨 위 버튼. 한 화면에 한 단계씩 — 지금 할 것, 왜 하나요, 큰 버튼 하나
(피아노 켜고 따라 부르기 / 타이머 켜고 하기 / 다 했어요). 피아노는 연습의 시작 음에서 자동으로 오르내리고, 한 번 다 오르내리면
체크되고, 단계가 끝나면 다음 단계로 넘어가요. 마지막에 연습 시간 저장과 목 상태 적기.

| 단계 | 항목 | 왜 |
|---|---|---|
| ① 준비 2분 | 자세·긴장 풀기 | 몸의 힘이 목으로 가지 않게 |
| ② 호흡 6분 | 히싱 ×5, 개호흡 20초×2 | (원래 항목 그대로) |
| ③ 립트릴·텅트릴 6분 | 1번 → 3번, 2번 → 4번 | 매일 하는 몸풀기 (책: 1~4번은 좋은 몸풀기라 계속 써도 됨) |
| ④ 스케일 연습 8분 | 앱이 골라 주는 연습 1개 ×3 | 책의 5~26번을 쉬운 것부터 하나씩 |
| ⑤ 노래에 적용 5분 | 몸 숙이기 → 울먹이기 → 모음 바꾸기 → 키 올리기 | 책 27~30번을 실제 노래에 |

- **오늘의 강도** (기초 연습 · 따라 하기 첫 화면): 가볍게 / 기본 / 도전. ④ 스케일 연습 반복이 2/3/4회, 그 뒤에 붙는 **복습**이 0/1/2개예요.
  복습은 이미 ‘잘 돼요’ 한 연습 중 오래 안 한 것부터(14~26번 우선, 5~13번은 2주 넘게 안 했을 때만) 골라요. 26번까지 마치면
  17~26번을 돌아가며 하는 **유지** 단계가 돼요. 전날 목 상태가 나빴으면 저장된 강도와 상관없이 그날은 가볍게.
- 부를 소리가 여러 개인 연습((a) 멈 (b) 거 …)은 한 번 할 때마다 다음 소리로 넘어가고, 다음 날 이어서 해요.
- 12·25번은 책대로 반음씩 **내려가며** 5번 해요. 단계마다 몇 분·몇 번·어떤 소리·▲▼인지 오늘 계획이 보여요.
- **1~30번 중 무엇을?** 매일 1~4번 + 스케일 연습 1개 + 27~30번. 스케일 연습은 5번부터 차례로, 편해지면
  ‘이제 잘 돼요’로 다음 번호. 이미 고음이 이어지면 ‘14번부터’로 건너뛰기. 단계 묶음: 이어지는 느낌 익히기(5~11) ·
  가성으로 길 내기(12~13, 필요할 때만) · 엣지 소리로 말하는 높이 찾기(14~18) · 끼익 빼고 진짜 소리로(19~22) ·
  모음 바꾸며 다듬기(23~26).
- 연습마다 쉬운 이름, 소리 내는 법, **이런 데 좋아요**, 방법 더 보기, 말 풀이(가슴소리·머리소리·끼익 소리 …)가 있어요.
- ①~③단계가 가벼운 날에도 하는 단계예요 (목 보호 규칙 2번). 목 보호 규칙 카드·노래할 때 기억할 것·발음 찾기·오늘의 기록은
  강의에서 온 그대로예요.

## 앱 안 업데이트

앱은 열 때와 돌아올 때(둘 다 6시간에 한 번까지) `main` 브랜치의 `songdiary/release/latest.json`을 확인해요.
새 버전이면 오늘 화면 위에 알려 주고, **업데이트**를 누르면 그 순간의 최신 목록을 다시 확인한 뒤
바뀐 파일만 받아서 앱 안에서 바꿔요 (다시 설치 X).

- 목록은 ECDSA P-256 키로 서명돼요. 앱에 든 공개 키와 맞지 않으면 받지 않아요. 파일마다 sha256도 확인해요.
- 파일은 `release/files/<sha256>`에서 받아요. 그래서 나중에 main의 `www/`가 바뀌어도 이미 내보낸 버전은 그대로 받아져요.
- 받은 버전은 안드로이드 앱 폴더(`files/ota/v<번호>`)에 두고 Capacitor의 `WebView.setServerBasePath`로 바꿔요.
  새 버전이 첫 화면까지 뜬 뒤에만 그 자리를 저장해요. 15초 안에 뜨지 않으면 이전 버전으로 돌아가고,
  뜨다가 멈춰서 앱을 닫은 경우에도 그 버전은 다시 권하지 않아요.
- 앱이 지금 어느 버전을 띄우는지는 안드로이드에 직접 물어서 정해요 (`getServerBasePath`). 필요 없는 다운로드만 지워요.
- 새 APK를 설치하면 안드로이드가 APK 안의 화면을 다시 써요 (Capacitor 기본 동작).
- 안드로이드 쪽(플러그인 등)이 바뀌어야 하는 버전은 `--min-apk`로 표시하고, 이때는 새 APK를 설치해야 해요.
  그런 버전은 오늘 화면에 알리지 않고 설정 > 앱 정보에서만 보여요.

새 버전 내보내기:

```bash
SONGDIARY_OTA_KEY=ota-key.pem python3 songdiary/tools/publish_update.py \
  --version 1.4.1 --code 7 --note "바뀐 점 한 줄" --note "또 한 줄"
git add songdiary && git commit -m "노래일기 1.4.1"
# PR을 main에 합치면 배포돼요
```

- `--code`는 버전마다 1씩 올려요 (APK의 versionCode와 같은 번호를 씀).
- 서명 키(`ota-key.pem`)는 저장소에 올리지 말 것. 잃어버리면 새 키를 넣은 APK를 한 번 새로 설치해야 해요.

## 계정·동기화

설정 → **계정·동기화**. 같은 이메일로 로그인한 기기끼리 기록·설정·녹음이 맞춰져요.
서버는 본인 Supabase 프로젝트이고, 준비 방법은 [`cloud/README.md`](cloud/README.md)에 있어요.

- 날마다 한 줄(`sd_days`)과 설정 한 줄(`sd_settings`)을 저장해요. 각 줄의 `rev`로 "내가 본 뒤로 바뀌었나"를 확인하고
  (`sd_push_day`가 비교 후 저장), 둘 다 바뀌었으면 백업 합치기와 같은 방식으로 합쳐요.
- 폰마다 마지막으로 맞춘 상태의 지문을 기억해서, 무엇이 바뀌었는지(백업 불러오기로 바뀐 것까지) 찾아 보내요.
- 알림 시각은 폰마다 따로예요. 녹음은 비공개 버킷 `sd-audio/<계정>/<녹음 id>`에 올리고, 기본은 Wi-Fi에서만 주고받아요.

## APK 다시 만들기

```bash
# 처음 한 번: 서명 키 만들기 (이 파일과 비밀번호를 잃어버리면 다음 업데이트 때 앱을 지웠다 깔아야 함)
keytool -genkeypair -alias songdiary -keyalg RSA -keysize 2048 -validity 36500 \
  -dname "CN=SongDiary, O=Personal, C=KR" -storetype PKCS12 -keystore songdiary-release.p12

# 기존 APK의 안드로이드 부분 + www/ → 새 APK (정렬 + v2 서명)
SONGDIARY_STOREPASS=... python3 songdiary/tools/build_apk.py \
  --base 노래일기-1.0.0.apk --www songdiary/www --keystore songdiary-release.p12 \
  --version-name 1.4.0 --version-code 6 --out 노래일기-1.4.0.apk
```

- 필요한 것: Python 3.8+, `cryptography` 패키지
- `--version-name`은 기존 값과 글자 수가 같아야 함 (예: `1.0.0` → `1.1.0`)
- 먼저 `publish_update.py`로 `www/release.json`을 같은 버전으로 만들어 두세요 (APK 안의 버전 = 앱이 아는 버전)
- 키 파일(`.p12`)은 저장소에 올리지 말 것

## 새 APK를 구글 드라이브로 (자동)

**앱 안 업데이트도 자동이에요.** 같은 빌드가 `songdiary-ota` 브랜치에 서명된 업데이트(`latest.json`, `files/<sha256>`)로 올라가고,
앱은 열 때(6시간에 한 번까지) 그걸 확인해서 오늘 화면 위에 ‘업데이트’를 띄워요. 누르면 바뀐 파일만 받아 바로 바뀌어요(다시 설치 X).
업데이트 서명 키는 드라이브의 APK 서명 키에서 매번 같게 만들어 내서(`tools/ci_release.py`) 따로 준비할 게 없어요.
버전은 빌드마다 `1.5.<실행 번호>`, 번호는 `100 + 실행 번호`. APK는 새 폰에 깔거나 안드로이드 쪽(`native/`)이 바뀌었을 때만
필요해요(그때는 워크플로의 `SONGDIARY_MIN_APK`를 올려요).

ReaderaPlus와 같은 방식이에요. 앱이 바뀐 푸시마다 GitHub Actions(`.github/workflows/songdiary-apk.yml`)가
`native/`(Capacitor 8 안드로이드 프로젝트)에 `www/`를 넣어 APK를 빌드하고, 구글 드라이브 `노래일기` 폴더에
`노래일기-<버전>.apk`로 올려요. 예전 APK는 휴지통으로 가요(30일 동안 되살릴 수 있음). Actions 탭에서 손으로 돌릴 수도 있고,
그 실행 화면의 Artifacts(`songdiary-apk`)에서도 7일 동안 받을 수 있어요.

처음 한 번 (폰으로도 됨):

1. script.google.com → **새 프로젝트**(ReaderaPlus 것 말고) → Code.gs를 [`tools/gdrive/upload.gs`](tools/gdrive/upload.gs)로 바꾸고,
   첫 줄 `KEY`를 비밀번호로 바꿔 저장 → 배포 → 새 배포 → 웹 앱(실행: 나, 액세스: 모든 사용자)
   → 권한 승인(고급 → 안전하지 않음으로 이동 → 허용) → 웹 앱 URL(`…/exec`) 복사.
2. 이 저장소 Settings → Secrets → Actions에 `SONGDIARY_DRIVE_URL`(웹 앱 주소), `SONGDIARY_DRIVE_KEY`(그 비밀번호).

- 다른 앱에서 공유한 녹음은 `ShareActivity`가 받아 복사한 뒤 앱을 평범하게 열어요. 공유가 앱 창(task)의 시작이 되면, 최근 앱에서 다시 열 때 안드로이드가 그 공유를 다시 보내려다 파일 권한이 없어 ‘앱을 열지 못했어요’가 떠요.
- `native/`: 앱이 쓰는 플러그인(App, Filesystem, Share, LocalNotifications; HTTP·WebView·SystemBars는 기본 포함)과
  `SongDiaryPlugin`(화면 켜 두기, 앱 설정 열기, 다른 앱에서 공유한 녹음 받기). 아이콘·스플래시는 `www/icon.svg`로 그렸어요.
- 서명 키는 첫 빌드 때 만들어 드라이브 `노래일기` 폴더의 `songdiary-signing.json`에 둬요. 지우지 마세요
  (다음 APK가 지금 깔린 앱 위에 설치되려면 같은 키여야 해요). 저장소가 공개라서 Actions 캐시에는 두지 않아요.
- 예전 APK(다른 키로 서명)가 깔린 폰은 처음 한 번 지우고 새로 깔아야 해요. 그 전에 설정 → 계정·동기화나 백업을 확인하세요.
- 시크릿이 없으면 빌드는 ‘설정 안 됨’만 알리고 끝나요. 실패하면 로그 마지막 줄이 어느 단계에서 왜 막혔는지 알려 줘요.
- 버전 이름·번호는 `www/release.json`의 것이에요. 웹 화면만 바뀐 버전은 APK 없이도 앱 안 업데이트로 받아져요.

## 브라우저에서 확인

`www/`를 아무 정적 서버로 열면 됩니다 (예: `npx serve songdiary/www`).
녹음 파일 공유 받기, 알림, 문서 폴더 저장 같은 안드로이드 기능만 빠지고 나머지는 그대로 동작해요.
